Executive overview

Bottom line: a capable, well-stocked catalogue (2 708 products, 231 categories) running on a stock commercial theme that was never fully finished. Two things dominate: the homepage returns HTTP 404 to every mobile and tablet browser (so most retail visitors land on a "Page not found" screen), and the site has no page cache, no CDN and no security hardening — TTFB of 3.2–12 s, an 845 KB public debug.log, open XML-RPC and user enumeration. Meanwhile the theme's own demo content (a demo email address, demo phone number and social links pointing at the theme author's ThemeForest portfolio) is still live in the production footer.

What was tested

  • Homepage + 15 key URLs (shop, category, product, contact, about, FAQ, cart, checkout, login, blog, legal) with HTTP probes from multiple user agents.
  • Full HTML source analysis of the 469 KB homepage (headings, images, forms, links, markup duplication, demo leftovers, trackers).
  • Lighthouse 12.8.2 mobile runs (about page, shop page) + attempted homepage runs.
  • Response headers, TLS/ALPN, redirects, compression, cache policy, robots.txt, XML sitemaps, WP REST API, exposed endpoints.
  • Structured data, meta/canonical/OG tags, internal link graph sampling, content quality review.

Scope & honesty notes

  • Passive black-box only: no logins, no brute force, no exploitation, no load testing. Probes were rate-limited and read-only.
  • Numbers are single-sample spot checks (16 Oct 2026) — treat timings as indicative, not lab-grade.
  • Server-side causes (e.g. the mobile 404) were diagnosed from outside; the exact plugin responsible needs a staging reproduction.
  • Pages that intermittently returned 503 or dropped connections during the audit are flagged as such.
